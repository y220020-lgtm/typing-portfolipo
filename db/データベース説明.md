# タイピング練習アプリ データベース説明

本ドキュメントは、「データベース仕様書（テーブル定義）」と、「それがアプリ上でどう動くのかの仕組み」を一体化させたスマートな解説書です。

---

## 1. データベースの全体構造（テーブル関連図）

アプリのデータを以下の7つのテーブルで管理します。「主キー」と「外部キー」を用いたリレーション構造により、データの重複や矛盾を防いでいます。

※ **注記**: SQLiteはテーブル定義時に管理テーブル（`sqlite_sequence` など）を自動生成するため、実際のデータベース内には8つ以上のテーブルが表示される場合がありますが、本設計の対象は7テーブルのみです。SQLiteの内部テーブルは設計対象外であり、削除・修正の対象ではありません。

| テーブル名 (英語) | 日本語訳 | 役割 |
| :--- | :--- | :--- |
| **users** | ユーザー | ユーザー（生徒）の基本情報を管理 |
| **stages** | ステージ | 学習の大分類カテゴリ（章）を定義 |
| **levels** | サブステージ | ステージに属する個別の練習問題セット（節）と「AIへの出題指示」を管理 |
| **keyboards** | キーボード | ユーザーごとの利用キーボードを登録 |
| **keys** | キー設定 | キーボード内における「キーと指の割り当て」を定義 |
| **logs** | プレイ記録 | 1問ごとのプレイ結果・履歴（※上書き不可・蓄積型） |
| **assignments** | 課題 | 教員が出す課題（レベル・締め切り・回数・正確率の条件） |

**【仕組みの概要（スマート解説）】**
* 全7テーブルから構成される、タイピング履歴の蓄積・分析に特化したDB設計です。
* **最大の特徴**: 「1問＝1レコードの徹底による高解像度な分析」と、表示順（sort_order）を利用した柔軟な問題管理を両立させています。

## 2. テーブル定義に沿ったシステムの動きと詳細解説

### ① ユーザー (`users`)
| カラム名 (英語) | 日本語訳 | 型 | 制約 | キー | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **id** | ID(学籍番号) | TEXT(文字) | NOT NULL | **主キー** | `y220020` のようなアルファベット混じりの学籍番号をそのままログインIDとして使うため、文字列型（TEXT）を採用。 |
| **name** | 名前 | TEXT(文字) | NOT NULL | | ユーザーの表示名。 |

**【各カラム（行）の詳しい役割】**
* **`id` (主キー)**: 生徒一人ひとりを特定するための絶対的な番号です。学籍番号をそのまま使うことで、パスワード入力を省きすぐに練習を始められます。
* **`name`**: 画面右上に表示するための名前で表示専用のデータです。

**【仕組みと動き】**
* 学生がログイン時に使うシンプルな「名簿」として機能します。


### ② ステージ (`stages`) / ③ サブステージ (`levels`)
**【stages テーブル】**
自由に追加・並べ替えが可能な「大分類」です。
| カラム名 (英語) | 日本語訳 | 型 | 制約 | キー | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **id** | ステージID | INTEGER(整数) | NOT NULL<br>AUTOINCREMENT | **主キー** | カテゴリの管理番号。（※自動採番。行を削除しても番号は再利用されないため、データの一貫性を保証） |
| **sort_order** | 表示順 | INTEGER(整数) | NOT NULL<br>DEFAULT 0 | | 画面に表示する順番（1, 2, 3...）。<br>※裏側の管理番号が `id: 3` の新しいステージでも、ここに `sort_order: 1` を設定すれば最初に表示されます。順序の変更に強い設計。 |
| **title** | タイトル | TEXT(文字) | NOT NULL | | 「ホームポジション基礎」「Python入門」など。 |
| **description**| 説明文 | TEXT(長文) | NULL許容 | | なにを学ぶステージなのかの概要。 |
| **is_active** | 表示フラグ | INTEGER(整数) | NOT NULL<br>DEFAULT 1 | **インデックス** | `0` で非表示（論理削除）。※練習の記録（`logs`）が指しているステージ・レベルは完全に削除できないため、非表示にして画面から外します。 |

**【levels テーブル】**
ステージ配下にぶら下がる、具体的な練習問題のセットです。
| カラム名 (英語) | 日本語訳 | 型 | 制約 | キー | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **id** | レベルID | INTEGER(整数) | NOT NULL<br>AUTOINCREMENT | **主キー** | 実際に出題される単位の管理番号。（※自動採番。番号の使い回しは発生しません。） |
| **stage_id** | ステージID | INTEGER(整数) | NOT NULL | **外部キー** | 【親: stages】どのステージに属しているか。 |
| **sort_order** | 表示順 | INTEGER(整数) | NOT NULL<br>DEFAULT 0 | | ステージ内での表示順。<br>※裏側の管理番号(`id`)に関係なく、ここに指定した数字の順番で画面に表示されます。問題の順序変更に対応。 |
| **title** | タイトル | TEXT(文字) | NOT NULL | | 「人差し指の練習」「for文の書き方」など。 |
| **description**| 説明文 | TEXT(長文) | NULL許容 | | この問題セットのクリア条件やコツなど。 |
| **prompt** | 生成プロンプト | TEXT(長文) | NOT NULL | | AIに問題を自動生成させるための指示文。 |
| **is_active** | 表示フラグ | INTEGER(整数) | NOT NULL<br>DEFAULT 1 | **インデックス** | `0` で非表示（論理削除）。非表示のレベルは学生の画面に出ず、出題もされません。過去の記録はそのまま残ります。 |
| **pass_accuracy** | 合格の目安 | REAL(小数) | NULL許容<br>CHECK 0より大きく1以下 | | 合格の目安となる正確率（例: `0.95` = 95%）。10問すべて解き、正確率がこの値以上のプレイを「合格」とします。`NULL` なら目安なし（自由に練習するレベル）。合格したかは保存せず、`logs` から毎回計算します。 |

**【仕組みと動き】**
* 練習問題の「大分類（stages）」と「個別問題（levels）」を階層化しています。
* `levels` の `prompt` に指示を入れておくだけで、アプリ側でAIと連携して**自動でタイピング問題が生成**されます。


### ④ キーボード (`keyboards`) / ⑤ キー設定 (`keys`)
**【keyboards テーブル】**
| カラム名 (英語) | 日本語訳 | 型 | 制約 | キー | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **id** | キーボードID | INTEGER(整数) | NOT NULL<br>AUTOINCREMENT | **主キー** | 管理番号。 |
| **user_id** | ユーザーID | TEXT(文字) | NOT NULL | **外部キー** | 【親: users】誰の所有しているキーボードか。 |
| **name** | 名前 | TEXT(文字) | NOT NULL | | 「学校のJIS」「自宅のUS配列」など自由に設定。 |
| **is_active** | 有効フラグ | INTEGER(整数) | NOT NULL<br>DEFAULT 1 | **インデックス** | `0`（無効）で論理削除。※過去の成績(`logs`)がエラーで消えたり壊れたりするのを防ぐため、完全削除はしません。 |
| **layout** | キーの並び | TEXT(文字) | NOT NULL<br>DEFAULT 'jis'<br>CHECK jis・us・keyball44・free | | 練習中に画面に出すキーボードの形（`jis` = JIS 配列、`us` = US 配列、`keyball44` = Keyball44 の左右分割、`free` = 自由な配列。組み替えたキーボード・キーの少ないキーボードなど、決まった形のないもの。登録した `keys` を担当の指ごとに並べて表示）。担当の指は `keys` で決まり、この値は指の分析には使いません。 |

**【keys テーブル】**
| カラム名 (英語) | 日本語訳 | 型 | 制約 | キー | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **id** | ID | INTEGER(整数) | NOT NULL<br>AUTOINCREMENT | **主キー** | 管理番号。 |
| **keyboard_id**| キーボードID | INTEGER(整数) | NOT NULL | **外部キー** | 【親: keyboards】どのキーボードの設定か。 |
| **char** | 文字 | TEXT(文字) | NOT NULL | | 対象のキー ('a' や 'Space', 'Enter' など)。 |
| **finger** | 担当の指 | TEXT(文字) | NOT NULL | | 「L1(左親指)〜L5」など。<br>※Ctrl+C等の同時押し(`L5+L2`)など特殊な入力にも柔軟に対応できるよう、数字とプラス記号の組み合わせで表現。 |

**【仕組みと動き】**
* ユーザー固有のキーボード構成と、柔軟な運指（指使い）をペアで記憶します。
* キーボード設定を削除したくなった場合も、`keyboards.is_active` を `0` にするだけで画面から見えなくなり、過去の成績データへの影響（バグ）を完全に防ぎます。


### ⑥ プレイ記録 (`logs`)
1問（1単語）ごとのプレイ結果を保存します。
| カラム名 (英語) | 日本語訳 | 型 | 制約 | キー | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **id** | ログID | INTEGER(整数) | NOT NULL<br>AUTOINCREMENT | **主キー** | 履歴番号。 |
| **session_id** | プレイ単位ID | TEXT(文字) | NOT NULL | **インデックス** | 「1回のプレイ」全体をまとめるための合言葉（例:`abc-123`）。これがないとプレイの流れが分からなくなります。 |
| **user_id** | ユーザーID | TEXT(文字) | NOT NULL | **外部キー** | 【親: users】誰のプレイ記録か。 |
| **level_id** | レベルID | INTEGER(整数) | NOT NULL | **外部キー** | 【親: levels】どの問題を解いたか。 |
| **keyboard_id**| キーボードID | INTEGER(整数) | NULL許容 | **外部キー** | 【親: keyboards】どのキーボードで解いたか（※専用設定がない場合はNULLを許容します）。 |
| **question_num**| 出題番号 | INTEGER(整数) | NOT NULL | | そのレベルの中で「何問目の出題だったか」を記録。<br>※これがないと、1回のプレイ(`session_id`)の流れが分からなくなります。 |
| **target** | 出題文 | TEXT(長文) | NOT NULL | | 本来打とうとした問題のテキスト（AI生成結果）。 |
| **typed** | 実入力文 | TEXT(長文) | NOT NULL | | ユーザーが実際に打ち込んでしまったテキスト（ミスを含む）。<br>※Enter を押した時点で入力欄に残っている文字列を保存します（Backspace で消した文字は含みません）。 |
| **start_time** | 開始日時 | TEXT(日時) | NOT NULL | | その問題の練習をスタートした日時（問題が画面に表示された時点）。<br>※形式は ISO8601・UTC・ミリ秒まで（例: `2026-10-16T01:23:45.678Z`）。 |
| **end_time** | 終了日時 | TEXT(日時) | NOT NULL | | その問題の練習が完了した日時（Enter を押した時点。形式は start_time と同じ）。（開始との差分が1問の所要時間） |

**【各カラム（行）の詳しい役割】**
* **`session_id`**: そのプレイ（例：10問セット）を一塊として管理するIDです。
* **`user_id`**: 成績が「誰のものか」を直接紐づけます。これにより、もし生徒が過去に作ったキーボード設定(`keyboards`)を削除してしまっても、成績データへの影響がありません。
* **`level_id`**: その成績が「どの問題を解いた時のものか」を示します。
* **`keyboard_id`**: 「その時、どの指使い設定でプレイしたか」を示します。
* **`target` / `typed`**: 画面に出題された1問分のテキストと、ユーザーが実際に打ち込んだ結果（ミスを含む）をそのまま保存します。スコア・WPM・正確率などは保存せず、表示や集計のたびに計算します（計算処理はアプリの画面とサーバーで共通のものを使います）。
* **`start_time` / `end_time`**: いつからいつまでその問題（単語）を打っていたかを記録します。この2つの差分を引き算すれば、その1文字（単語）に何秒かかったかが分かります。

**【仕組みと動き】**
* **1問＝1レコード設計**: 画面に出た問題（例：`jjjj`）を打ち終わり、生徒が**「エンターキー」を押して次の問題へ進んだ瞬間**に、その1問分のデータがデータベースに自動保存されます。
* 1問完結型で蓄積することで、どの文字やどの指での入力に時間がかかっているかといった、極めて詳細な分析を可能にします。
* 旧記録への上書きは決してされず、すべて**「過去の履歴」としてシステムに蓄積**され続けます。
* この方針はデータベース側でも保証しており、`logs` に上書き（UPDATE）や削除（DELETE）を行おうとすると、トリガー（`logs_no_update`・`logs_no_delete`）がエラーで拒否します。

### ⑦ 課題 (`assignments`)
教員が出す課題です。「いつまでに、どのレベルを、何回、どの正確率で」を保存します。達成したかは保存せず、`logs` から毎回計算します（🅲 と同じ考え方）。
| カラム名 (英語) | 日本語訳 | 型 | 制約 | キー | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **id** | 課題ID | INTEGER(整数) | NOT NULL<br>AUTOINCREMENT | **主キー** | 管理番号。 |
| **title** | 課題名 | TEXT(文字) | NOT NULL | | 「人差し指の練習を3回」など。 |
| **level_id** | レベルID | INTEGER(整数) | NOT NULL | **外部キー** | 【親: levels】どのレベルの課題か。 |
| **due_at** | 締め切り | TEXT(日時) | NOT NULL | | ISO8601・UTC・ミリ秒（`logs` の日時と同じ形式）。画面では日本時間の日付で入力し、その日の終わり（23:59:59.999）を保存します。 |
| **required_plays** | 必要な回数 | INTEGER(整数) | NOT NULL<br>DEFAULT 1<br>CHECK 1以上 | | 条件を満たすプレイが何回あれば達成か。 |
| **min_accuracy** | 正確率の条件 | REAL(小数) | NULL許容<br>CHECK 0より大きく1以下 | | 数えるプレイの正確率の下限。`NULL` ならレベルの `pass_accuracy` を使い、それもなければ10問解いたプレイを数えます。 |
| **created_at** | 作成日時 | TEXT(日時) | NOT NULL | | 課題を出した日時。これより前のプレイは数えません。 |
| **is_active** | 有効フラグ | INTEGER(整数) | NOT NULL<br>DEFAULT 1 | **インデックス** | `0` で削除（論理削除）。学生の画面から消えます。 |

> 💡 **達成の数え方**: 課題を出した日時（`created_at`）から締め切り（`due_at`）までに、そのレベルで、10問すべて解き、正確率の条件を満たしたプレイ（`session_id` ごと）の数が `required_plays` 以上なら達成です。

## 3. データベース運用方針（将来への備えと設計の安全性）

### 🅰️ 問題の追加と表示順の管理
* 固定された問題群にとらわれず、新しい問題をDBに追加すれば即座に画面に反映されます。
* ステージおよびレベルの表示順は `sort_order` カラムで管理します。
* 不要になったステージ・レベルは `is_active` を `0` にして非表示にします（論理削除）。練習の記録が指しているものは完全には削除できないためです。非表示のものは学生の画面に出ず、出題もされませんが、過去の記録はそのまま残り、分析にも使われます。

### 🅱️ スコアリングルールの変更（関心の分離）
* 運用途中で「やっぱりスコアの計算式を変えたい」「WPM以外にも新しい独自指標を導入したい」という教員からの要望が出る可能性があります。これに完璧に対応できる設計です。
* 対策として、データベースにはスコア・WPM・正確率などの「計算結果」を一切保存しません。すべて `target`・`typed`・`start_time`・`end_time` から動的に計算します（計算処理はアプリの画面とサーバーで共通のもの。教員向けの集計や CSV 出力はサーバーで計算します）。

### 🅲 AI連携とキャッシュ戦略（コスト・速度最適化）
* `levels` テーブルの `prompt` を使ってAI（OpenAIやGemini等）に問題を自動生成させる際、生徒がプレイするたびに毎回AIを呼び出すと、APIの利用料金が非常に高くなってしまいます。
* **対策**: 
  1. APIキーの漏洩を防ぐため、AIとの通信は必ずフロントエンド（画面）ではなく**バックエンド（サーバー側）**で行います。
  2. 一度AIが生成した問題のリストは、サーバー側で一定期間（例：1時間〜1日）**キャッシュ（一時保存）**して使い回す設計とします。
  これにより、「APIコストの極小化」と「待ち時間ゼロのサクサク動くプレイ環境」を両立させることができます。

## 修正歴
* **SQLiteの仕様に合わせたデータ型修正**
  * `boolean(真偽値)` を `INTEGER(整数)` に変更し、デフォルト値を `1`、無効値を `0` に変更（SQLiteにはBOOLEAN型が存在せずINTEGERで代用されるため）。
  * `varchar(文字)` を `TEXT(文字)` に変更（SQLiteにはVARCHAR型がなく、文字列はすべてTEXTとして扱われるため）。
  * `datetime(日時)` を `TEXT(日時)` に変更（SQLiteにはDATETIME型がなく、一般的にTEXTのISO8601形式などで保存されるため）。
* **2026-10-02: 定義と実際のデータベースの一致**
  * `users.id` に NOT NULL を明示し、`logs` に上書き・削除を禁止するトリガーを追加。
  * 表の型表記を実際の定義（`INTEGER`・`TEXT`・`AUTOINCREMENT`）に統一。
  * 外部キーの有効化とインデックスの一覧は `データベース仕様書.md` §3 を参照。
* **2026-10-16: 記録の形式を明記**（`typed` の内容と日時の形式。詳細は `データベース仕様書.md`）
* **2026-10-16: スコアの計算場所を実装に合わせて修正**（「フロントエンドで計算」→「画面とサーバーで共通の計算処理」。DB の構造は変更なし）
* **2026-10-16: ステージ・レベルを非表示にできるようにした**（`stages`・`levels` に `is_active` を追加。詳細と理由は `データベース仕様書.md` の修正歴）
* **2026-10-23: 合格の目安と課題を追加**（`levels` に `pass_accuracy`、新しい表 `assignments`。合格・達成は保存せず `logs` から計算。詳細は `データベース仕様書.md` の修正歴）
