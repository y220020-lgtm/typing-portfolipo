# タイピング練習・学習分析 Web システム 設計書

本書は `app/` に実装した Web システムの構成・機能・API・データの扱いを、実装に基づいて説明する。
データベースの設計そのもの（7 テーブルの定義と設計思想）は 3 文書（`データベース説明.md`・`データベース仕様書.md`・`データベース作成の説明.md`）と `schema.sql` を参照。

- 動かし方: `app/README.md`

---

## 1. システムの目的と範囲

教育機関でのタイピング練習を支援し、練習の記録から学習状況を分析できるようにする。

| 利用者 | できること |
|---|---|
| 学生 | 学籍番号でログイン → レベルを選んで 10 問練習 → 結果（WPM・正確率・ミスした位置）を見る。これまでの記録（推移・間違えやすい文字・指ごとのミス率）を見る |
| 教員 | 学生一覧（プレイ回数・問題数・最後の練習・成績）→ 学生ごとの学習状況を見る。記録を CSV で取り出す。ステージ・レベル（表示順・タイトル・説明・AI への指示文）を管理する |

範囲外（実装していないもの）: パスワードによるログイン、大学独自の全学認証（Shibboleth など）、グループ分け・複数クラスの区別（DB に表が要るため、本人の判断で作らない。学生一覧の並べ替え・検索で整理する）。研究室 Web サーバーの SSO（oauth2-proxy）からの受け取りはアプリ側を実装済み（§4.1）。研究室サーバー側の設定は未実施。

## 3. データベースの使い方

DB の構造は正本（`schema.sql`）のまま変更していない。Web システムは 7 テーブルを次のように使う。

| テーブル | 読む | 書く |
|---|---|---|
| users | ログイン、学生一覧、名前の表示 | 教員の学生の追加・名前の変更・削除（練習の記録がない学生だけ） |
| stages / levels | レベル選択、出題（`levels.prompt` を AI に送る）。非表示（`is_active = 0`）のものは学生の画面と出題に出さない | 教員の管理画面（追加・変更・削除。2026-10-23 から「非表示」は「削除」に統一。記録のあるものは記録を守るため行を残して `is_active = 0` にし、画面から消す） |
| keyboards | 学生が使うキーボードの選択（`is_active = 1` のみ） | 学生を追加するときに標準のキーボード（Keyball44）を 1 つ付ける。有効なキーボードが 1 台もない人（教員・全部削除した学生）には、開いたときに「標準のキーボード（JIS 配列）」を作る（2026-11-13）。学生は「キーボードの設定」で追加（初めの割り当ては Keyball44・JIS・US・空のひな形、または自分のキーボードの写し。キーの並びは JIS・US・Keyball44・自由な配列）・名前の変更・削除（`is_active = 0`）ができる。学生の削除で消す |
| keys | 指ごとのミス率（文字 → 指の対応） | 同上（標準の 46 キー。`app/server/defaultKeys.ts`。タイピング.db の既存のキーボードと同じ割り当て） |
| logs | 結果、学習分析、CSV、評価用の集計 | 1 問ごとに 1 行追加（UPDATE / DELETE はトリガーで禁止） |

- 接続のたびに `PRAGMA foreign_keys = ON` を実行する（`server/db.ts`）。
- 開発・テストでは `schema.sql` と `seed/seed.sql` から別の DB を作る。正本の `タイピング.db` は読み書きしない（`npm run report` で読み取り専用で開く場合を除く）。
- `seed/seed.sql` は `タイピング.db` の users / stages / levels / keyboards / keys と同じ内容（`sqlite3 db/タイピング.db .dump` の INSERT 文と diff で一致を確認）。

### 3.1 logs に記録する値

| カラム | 値の決め方 |
|---|---|
| session_id | プレイ開始時にサーバーが UUID を発行 |
| user_id | ログイン中のユーザー（トークンから決める。画面から送られた値は使わない） |
| level_id / keyboard_id | プレイ開始時に選んだもの（サーバーが覚えている値） |
| question_num | 1 から順番どおり |
| target | プレイ開始時にサーバーが決めた出題文 |
| typed | Enter を押した時点の入力欄の文字列（Backspace で消した文字は含まない） |
| start_time | 問題が画面に表示された時刻（ISO8601・UTC・ミリ秒） |
| end_time | Enter を押した時刻（同上） |

## 4. 機能の詳細

### 4.1 ログインと権限

- ログインの方式は 2 つ（`AUTH_MODE`）。
  - `local`（既定）: 学生は `users` に登録された学籍番号だけでログインする（設計どおりパスワードなし）。
  - `proxy`（指導教員の指示「SSO でログインし、Web サーバーを経由して API にアクセスする」に対応）: ログインは研究室 Web サーバーの oauth2-proxy（大学の Google アカウント）が行い、アプリは要求ごとに、oauth2-proxy が付ける本人のメールアドレスのヘッダーで判定する。メールの @ より前を学籍番号として `users` と照らし合わせる（DB の構造は変えない）。ヘッダーは、プロキシとアプリだけが知る合言葉（`PROXY_SECRET`）のヘッダーが付いた要求のときだけ信じる。教員は `TEACHER_EMAILS` のメールアドレス。手順は `app/README.md`
- 以下の学生・教員・トークンの説明は `local` の場合。
- 学生: `users` に登録された学籍番号だけでログインする（設計どおりパスワードなし）。
- 教員: 起動時の環境変数 `TEACHER_IDS`（ID の一覧）で指定し、その ID だけでログインする（2026-11-13 に合言葉をなくした。本人の指示）。`users` には役割の列がないため、DB の構造を変えずに教員を区別する方法として選んだ。
- ログインするとトークン（ランダムな 48 桁の 16 進数）を発行し、サーバーのメモリに保持する。最後に使ってから 12 時間で無効になる。サーバーを再起動すると全員ログインし直しになる。
- 学生は自分の記録だけ、教員は全員の記録を見られる。教員用 API は学生のトークンでは 403 になる。
- 教員も、メニューの「練習（学生の画面）」から学生と同じ画面で練習できる（2026-11-13）。記録の外部キーのため、初めて練習の機能を使うときに教員の ID で `users` に行を作る（DB の構造は変えない）。教員の記録は学生一覧・課題・クラス全体の苦手から除き、CSV には `user_id` が教員の ID のまま出る。

### 4.2 出題

1. 学生がレベルを選ぶと、サーバーが `session_id` と 10 問を決めて返す（この時点では DB に書かない）。
2. AI の設定（`AI_BASE_URL`・`AI_MODEL`）があれば、`levels.prompt` を AI に送って問題を作り、レベルごとに一定時間（既定 1 時間）キャッシュする。キャッシュがある間は AI を呼ばない（`データベース仕様書.md` 🅳 のキャッシュ戦略）。
3. AI の設定がない・失敗した・使える問題が返らなかった場合は、レベルの決まり（6.）に合う問題で出題する（決まりのないレベルは固定問題 `server/questions.ts`）。
4. AI の返答は、最初の JSON 文字列配列だけを読み、40 文字以内で、半角の英数字・記号・空白、またはひらがな・カタカナ・漢字・日本語の句読点だけのものを問題にする（全角の英数字・絵文字は使わない）。形の崩れた問題が `logs` に永久に残らないよう、読めない返答は推測で読み取らない。
5. 教員がレベルの指示文を変えたら、そのレベルのキャッシュ（問い合わせ中のものを含む）を捨てる。
6. レベルの決まり（`server/levelRules.ts`、2026-11-13 追加）: レベル名と指示文の言葉（上の段・人差し指・ひらがな など）から、出してよい問題の範囲を決める（例: 上の段は q〜p のキーだけ）。AI の問題は範囲に合うものだけを出し、足りない分は範囲に合う問題で補う。AI への指示にも範囲を書き添える。
7. レベルごとの苦手克服（`POST /api/levels/:id/training`、2026-11-13 追加）: 通常のレベルの結果画面の「このレベルの苦手を克服する問題へ」から。そのレベルの範囲に合う最近の記録（50 問まで）から弱点を要約し、苦手克服トレーニングと同じ形で AI に分析と問題を頼む。問題は 6. の範囲に合うものだけを出し、足りない分は範囲の中で苦手な文字を含む問題で補う（キーのレベルはキーの並びを作る。単語のレベルは用意した候補から選ぶので、苦手な文字を含む候補が少ないことがある）。キーのレベルでは苦手な文字もそのレベルのキーに限る。記録はそのレベルの記録として保存し（合格・課題にも数える）、AI の返事はキャッシュしない（学生ごとに違うため）。

### 4.3 記録の保存と検証

`logs` は追加のみで、あとから直せない。そのため保存前に次を確かめ、満たさなければ保存しない（400 / 404 / 409）。

| 確認 | 理由 |
|---|---|
| トークンの持ち主のプレイか | なりすましで他人の記録を作らせない |
| 問題番号が 1 から順番どおりか | 飛ばし・先取りで成績を作れないように |
| 同じ問題番号の再送は既存の行を返す | 通信の再送で二重に記録しない |
| 日時が実在する ISO8601・UTC・ミリ秒か | 2 月 31 日のような値で集計が壊れないように |
| 開始がプレイ開始（または前の問題の終了）以降、終了がサーバーの現在時刻以前（許容 5 秒） | 所要時間を偽って WPM を作れないように |
| プレイ開始から 2 時間以内か | 古いプレイへの追記を防ぐ |
| 入力が出題の文字数 ＋ 200 文字以内か | 極端に長い入力を防ぐ |
| レベルがまだ存在するか | プレイ中に削除された場合は 409（記録できない旨を表示） |

端末の時計がずれていても記録がずれないよう、画面はプレイ開始時にサーバー時刻を受け取り、その差を補正して時刻を送る。

### 4.4 スコアと学習分析の計算

スコアは DB に保存せず、`logs` の生データから毎回計算する（`データベース説明.md` 🅱️）。計算処理（`shared/`）は画面とサーバーで共通。

| 指標 | 計算 |
|---|---|
| 所要時間 | `end_time` − `start_time`（秒） |
| 正しく打てた文字数 | 出題と同じ位置で一致した文字数 |
| 正確率 | 正しく打てた文字数 ÷（出題の文字数 ＋ 出題より多く打った文字数） |
| WPM | 正しく打てた文字数 ÷ 5 ÷ 所要時間（分） |
| 文字/分 | 正しく打てた文字数 ÷ 所要時間（分）。日本語の問題が中心のプレイでは、結果画面にこちらを主に出す（出題の文字の半分以上が半角以外なら日本語） |
| プレイごとの推移 | `session_id` ごとに上を計算し、最初の問題の開始時刻順に並べる |
| 間違えやすい文字 | 出題文の各文字について、ミスした回数 ÷ 出題された回数 |
| 指ごとのミス率 | プレイで使ったキーボードの `keys` で文字を指（`finger`）に対応させて集計。英字は大文字、`;` は `KC_SCLN`、`/` は `KC_SLSH`、空白は `Space` として照合。キーボード未指定・対応なしは「不明」 |

タイムゾーン表記のない日時（`タイピング.db` のデモデータ 5 件）は UTC として扱う。

### 4.5 CSV 出力

教員は `logs` の全記録を CSV で取り出せる。生データの各列に、その場で計算した所要時間・正しく打てた文字数・出題の文字数・正確率・WPM を加える。Excel で開けるよう BOM 付き UTF-8・CRLF とし、`= + - @` などで始まる文字列には先頭に `'` を付けて数式として実行されないようにする。

## 6. 画面

| 画面 | 利用者 | 内容 |
|---|---|---|
| ログイン | 共通 | 学籍番号（教員は教員の ID。同じ欄） |
| 教員のメニュー | 教員 | 学生の学習状況・ステージ・レベルの管理・課題・「練習（学生の画面）」のタブで行き来する。練習の画面では学生と同じ機能を使える（記録は教員の ID で残り、学生一覧・課題・クラス全体の苦手には入らない） |
| キーボードの設定 | 学生 | 練習に使うキーボードの選択（「使用中」の印。トップの「使うキーボード」と同じで、端末に保存）、キーボードの追加・名前の変更・削除、キーと担当の指（L1〜L5・R1〜R5。同時押しは 2 本目の指を選び L5+L2 の形で保存）の割り当て。キーは自由に追加・外せる（キーの少ないキーボード・組み替えたキーボードも登録できる）。自由な配列のキーボードは、練習中の画面のキーボードに登録したキーを指ごとに並べる。「キーを押して登録」では、文字を決まった順（A〜Z・数字・記号・スペースなど）に 1 つずつ出し、その文字に使うキーを押してもらって、押したキーが何の文字を出すかを問わずその文字として登録する（例: 「F」のときに q の位置のキーを押せば、そのキーが F）。指は画面の手から選び（数字キー 1〜0 でも選べる）、押した位置の標準の指を候補に出す（Enter で決定）。ないキー（Esc）は飛ばし、1 つ前に戻れる。同時押しはどんな組み合わせでもよく（例: A と B を一緒に押して C、Ctrl と A を一緒に押して…）、押したボタンをすべて離した時点の組み合わせを 1 つとして受け取り、ボタンごとに指を選ぶ（例: L2+R5）。同じ組み合わせを 2 つの文字に登録しようとすると止める。重なりの確認は登録の間だけ（DB には押したボタンの位置を保存しないため）。割り当ての一覧は、キーの文字を大きく出したカードで並べ（英字・数字・記号・そのほかの順）、カードを押すと 10 本の指のボタンが出て、押すだけで指を選べる（2 本以上で同時押し）。Fn などブラウザに届かないキーは手で追加する。練習の記録があるキーボードは割り当てを変えられない（過去の記録の指の分析を変えないため。写して新しく作る） |
| レベル選択 | 学生 | 課題（進み具合・締め切り・達成）、キーボードの選択、苦手克服トレーニング、ステージごとのレベル（合格の目安・合格済みの印）、「これまでの記録を見る」 |
| タイピング | 学生 | 出題（打った文字を緑 / 赤で表示、空白は ␣）、入力欄、進み具合、打っている最中の WPM・正確率・時間、画面のキーボード（次に打つキーと担当の指を光らせる。指は選んだキーボードの keys から。日本語の問題では、次のかなのローマ字（例: 「ピュ」= pyu）とその最初のキーを示す。漢字は読みが決まらないので「読みをローマ字で入力」と示す）。出題より多く打った文字は入力欄の下で知らせる。Enter で次の問題へ |
| 結果 | 学生 | WPM・正確率・合計時間、問題ごとの入力とミスの位置、合格したか（合格の目安があるレベル）、「このレベルの苦手を克服する問題へ」（そのレベルの範囲で、記録から苦手を補う問題。§4.2 の 7）、「間違えた問題だけもう一度」、「次のレベルへ」（合格したとき、または目安のないレベル） |
| これまでの記録 | 学生 / 教員 | 合計の成績、WPM と正確率の推移（別々の折れ線）、間違えやすい文字・指ごとのミス率（横棒）、プレイの一覧。グラフは表に切り替えられる |
| 学生一覧 | 教員 | 学生ごとのプレイ回数・問題数・成績・最後の練習、クラス全体の苦手（文字・指）、CSV 保存 |
| 課題 | 教員 | 課題を出す（レベル・締め切り・回数・正確率の条件）・編集・削除、学生ごとの達成状況 |
| ステージ・レベルの管理 | 教員 | 表示順・タイトル・説明・AI への指示文・合格の目安（正確率。空欄なら自由に練習）の変更、追加、削除（記録のあるものは記録を残して画面から消す） |

画面のデザインの決まり「Futuristic Typing Lab」（2026-10-23 改訂。`app/web/src/style.css` の先頭の変数と、末尾のテーマで決める）:

| 項目 | 決まり |
|---|---|
| テーマ | ライト / ダークを、ヘッダー右上のボタンで切り替える。選んだテーマは端末（ブラウザ）に保存し、再読み込み後も使う。選んでいなければ端末（OS）の設定に合わせる。色は役割の変数（背景・区画・文字・練習の画面など）で決め、テーマごとに値を入れ替える |
| 色 | 濃紺（ネイビー）を土台に、シアン・エレクトリックブルー・パープル・マゼンタを光のアクセントにする。ヘッダーはどちらのテーマでも濃紺 |
| 光と動き | グラデーションと発光は、進み具合・主なボタン・グラフ・今打つ文字など意味のある所だけ。アニメーションは 0.2〜0.35 秒。端末で動きを減らす設定のときは止める |
| 文字 | 見出し（1.3rem・太字）、小見出し（1.05rem）、本文（1rem）、補助（0.875rem）の 4 段。コントラストは本文 4.5:1 以上・大きい文字 3:1 以上を計算で確認（作業ログ） |
| 練習の画面 | 問題の文字と入力欄をいちばん目立たせる。文字の状態は色だけに頼らない（正しい = 色、間違い = 色 + 背景 + 波線、今の文字 = 枠、まだ = 普通の濃さ）。空白は ␣ を点線の枠で示す。WPM・正確率・時間は区画に分けて数値を大きく。画面のキーボードは小さく控えめな補助にし、光るのは次のキーと指だけ |
| 表示する数値 | `logs` から計算した実際の値だけ（架空のグラフや数値は出さない） |

| 項目 | 決まり |
|---|---|
| 画面の役割 | 学生のトップは練習を始める操作を先に、タイピングは 出題 → 入力欄 → 進み具合・操作の案内 を最優先にし、苦手の分析は補助として下に置く。教員の画面は下線のタブと表で、確認と管理を優先する |

## 7. 設計上の判断と限界

| 項目 | 判断・限界 |
|---|---|
| 本人確認 | `AUTH_MODE=local`（既定）では学籍番号だけでログインできる（設計どおり）。他人の学籍番号を知っていれば、その人として練習できてしまう。`AUTH_MODE=proxy`（研究室 Web サーバーの SSO、§4.1）では大学の Google アカウントで本人を確かめる。ただし研究室サーバー側の設定は未実施で、本物の SSO では未確認 |
| 教員の区別 | DB を変えず、環境変数で指定する。教員の一覧を画面から変えることはできない |
| ログインとプレイの状態 | サーバーのメモリに置く。再起動するとログインし直し、プレイ中の問題は続けられない（保存済みの記録は残る） |
| 正確率の比べ方 | 位置ごとに比べる。途中で 1 文字抜けたり増えたりすると、それ以降の文字もミスになる |
| 日本語の入力 | 採点は変換を確定した後の文字で、出題と 1 文字ずつ比べる。変換の途中や打ったキーは記録しない。そのため日本語の問題では、指ごとのミス率は出せない（キーボードの設定は英字のキーに指を割り当てているため）。画面は変換中の文字を色付けしないが、実際の日本語入力（IME）での確認は行っていない（E2E は確定した文字を直接入力している） |
| typed の内容 | Enter 時点の文字列のみ。Backspace で直した過程や、キーごとの打鍵時刻は記録しない。そのため「どのキーで時間がかかったか」は分析できず、時間は 1 問単位 |
| 指の対応 | `keys` に登録された文字だけ。キーボードを指定しないプレイは「不明」 |
| AI | OpenAI 互換 API。AI モックのコンテナで確認し、研究室の Qwen（vLLM）でも通常のレベル・苦手克服トレーニングの問題作成を確認済み（2026-10-23〜11-13、作業ログ）。AI は指示を守らないことがあるため、出題はレベルの決まり（§4.2 の 6）で選び直す |
| 同時利用 | SQLite（WAL）。1 台のサーバーで数十人程度を想定。負荷試験は未実施 |
| 公開範囲 | 既定は VM 内（127.0.0.1）のみで待ち受ける |
